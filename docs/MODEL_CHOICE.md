# Model choice

The checklist judge, the drafter, and the classifier on approach 2 and approach 3 read the model id from `LLM_MODEL` in `.env`. The id is kept exactly as it is written. It does not approve a case, and it does not post a record. `.env.example` sets the main model to `gpt-6-luna` with `LLM_API_STYLE=openai`. An empty `LLM_MODEL` uses `claude-haiku-4-5`. An empty `LLM_API_STYLE` uses `anthropic`. When `LLM_FALLBACK_API_KEY` and `LLM_FALLBACK_BASE_URL` are set, a failed call asks `LLM_FALLBACK_MODEL` once. `.env.example` sets that fallback to `claude-haiku-5-5` with `LLM_FALLBACK_API_STYLE=anthropic`. An empty fallback model uses `claude-haiku-5-5`. An empty fallback style uses `anthropic`. An empty key or host means there is no fallback. The saved record names the model that answered, plus `fallback_used` and `primary_failure` when the first call failed. Those two fields stay in the audit and in the closed technical details on the comparison page.

The checklist judge runs after the deterministic checklist has already passed, and only when `FEATURE_LLM_REVIEW=block`. It returns `pass` or `block` plus a short paragraph for the reviewer. It does not set classification, routing, policy, facts, deadline, or citations. The customer message stays the fixed template, so a judge failure cannot change that sentence.

Approaches 2 and 3 call that same model only when the rules leave the case open. A labeled denial, a conflict, and a rules class of unsupported, duplicate, or service are not sent. Ambiguous with no conflict may be sent. Unauthorized from complaint wording may be sent only when authorization is not supplied. The complaint is redacted before the call. A proposed class is kept only when the labeled authorization allows it: unauthorized only when the label is not supplied or denied; duplicate and service only when the label is confirmed or not supplied. A confirmed label on an unauthorized proposal does not stand, and the case goes to manual review. A denied label never reaches the model. Any other class with that label is a hard failure. Evidence is accepted only when it is exact complaint text after whitespace is collapsed. A quote that is not in the complaint is rejected, and approach 2 then keeps the rules class.

Approach 3 asks Jev first. Jev's model name defaults to `jev-latest`. The threshold in `config/rules/classifier.yaml` is a placeholder, `0.70`. A tie, a probability under that threshold, or an ambiguous option does not assign a class. An ambiguous Jev answer goes to manual review and does not call Clef or the configured model. When Jev returns a class and it matches the rules, that class is kept and the configured model is not called. When Jev is missing or its call fails, approach 3 asks Clef-flash with the same choice payload plus `instructions` on the choice question. An ambiguous Clef answer goes to manual review and does not call the configured model. A Clef class that matches the rules is kept. A disagreement asks the configured model, and that class stands only when it matches the rules or the ranker. A rejected reply still goes to manual review. If there is no configured-model client, or that call cannot run, the rules class stays (`ranker_disagreed_no_model`). When no ranker returns a class, the configured model is asked, or the rules class stays when that client is missing (`rules_only`, or `model_failed` when a ranker call failed). Jev is priced from the vendor list in `config/rules/cost.yaml` (0.042 USD per million input tokens, output free). The source is the TypeSafe blog "Introducing System One Models & Jev", https://typesafe.ai/blog/introducing-system-one-models-and-jev (published 2026-09-15; early access), checked 2026-10-27. A call records that list price when the reply includes token counts. A reply with no token count stays `unpriced` and its stored number is not treated as a price. The `clef-flash` input figure 0.038 has no verified public source yet and is unverified. Output tokens on that row are 0.00. An empty `JEV_BASE_URL` or `JEV_API_KEY` skips Jev. An empty `CLEF_API_KEY` or `CLEF_ACCOUNT_ID` skips Clef. A failed Clef call stores a short failure label, not the response body.

|---|---|
| Model id | `.env.example` sets `gpt-6-luna`. The id is kept exactly as written. An empty `LLM_MODEL` uses `claude-haiku-4-5`. |
| Fallback | `.env.example` sets `LLM_FALLBACK_MODEL=claude-haiku-5-5` and `LLM_FALLBACK_API_STYLE=anthropic`. Empty key or host means no fallback. Empty model uses `claude-haiku-5-5`. Empty style uses `anthropic`. |
| API style | `.env.example` sets `LLM_API_STYLE=openai` for the main model. An empty `LLM_API_STYLE` uses `anthropic`. `openai` posts chat completions and sends the key as `Authorization: Bearer`. `anthropic` posts messages and sends the key as `x-api-key`. The host is `AZURE_BASE_URL` in `.env`. It is not written in this file. A model call fails when that variable is empty. |
| Credential | `LLM_API_KEY` in `.env`. Empty means no configured-model call. |
| Ranker | Jev, then Clef when Jev is missing or the call fails. `JEV_BASE_URL`, `JEV_API_KEY`, `JEV_MODEL`. `.env.example` sets `JEV_MODEL=jev-latest`. Leave the url and the key empty until a host is chosen. An empty `JEV_MODEL` uses `jev-latest`. |
| Clef fallback | `CLEF_API_KEY`, `CLEF_ACCOUNT_ID`, `CLEF_MODEL`. Empty key or account skips it. Empty model uses `clef-flash`. The account id and key are not written in this file. |
| Checklist judge | `dispute-copilot agent-review`, after the checklist passes, when `FEATURE_LLM_REVIEW=block` |
| Classifier | Approach 2, and approach 3 on an eligible case when Jev and Clef are absent or failed, or when a ranker disagrees with the rules |
| Judge fallback | When the fallback key and host are set, one failed call asks `LLM_FALLBACK_MODEL` once. If that call also fails, the review keeps the existing failure note. `FEATURE_LLM_REVIEW=off` skips the call and leaves the checklist result |
| CI / tests | `LLM_PROVIDER=null` and approach 1. Run the suite with `FEATURE_LLM_REVIEW=off`. A missing key cannot fail the live check, and the jobs do not set `CLASSIFIER_APPROACH` |
| Configured-model cost | `config/rules/cost.yaml` prices `claude-haiku-5-5` from list at 0.10 USD per million input tokens and 0.50 USD per million output tokens for prompts up to 100,000 tokens. Prompts over 100K tokens are not modelled. `claude-haiku-4-5` is not listed, so that id is `no price configured for claude-haiku-4-5`. `gpt-6-luna` is the Azure Global Standard short-context list at 0.10 in and 0.50 out. Cached input, long-context rates (0.20 / 0.75), and Data Zone premiums are not modelled. The Azure invoice may differ from list. No measured token counts are recorded here |
| Jev cost | Priced from the vendor list in `config/rules/cost.yaml`: 0.042 USD per million input tokens, output free. Source: TypeSafe blog "Introducing System One Models & Jev", https://typesafe.ai/blog/introducing-system-one-models-and-jev (published 2026-09-15; early access), checked 2026-10-27. Vendor list price, may change; the invoice may differ. A call is priced when the reply includes token counts. A stored number with status `unpriced` is not treated as a price |
| Clef-flash cost | `config/rules/cost.yaml` has 0.038 USD per million input tokens and 0.00 output. That input figure has no verified public source yet and is unverified. Token counts come from the provider `usage` object when present |

Structured output is parsed in the app from one JSON object. There is no schema enforcement on the provider call and no repair retry. A judge reply that is not `pass` or `block` with two to four sentences is stored as a block. A classifier reply is one JSON object with `class`, `reason`, and `evidence`.
