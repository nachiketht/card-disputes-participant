# Model choice

The checklist judge, the drafter, and the classifier on approach 2 and approach 3 read the model id from `LLM_MODEL` in `.env`. The id is kept exactly as it is written. It does not approve a case, and it does not post a record. When `LLM_FALLBACK_API_KEY` and `LLM_FALLBACK_BASE_URL` are set, a failed call asks `LLM_FALLBACK_MODEL` once. An empty fallback model uses `claude-haiku-5-5`. An empty key or host means there is no fallback. The saved record names the model that answered, plus `fallback_used` and `primary_failure` when the first call failed. Those two fields stay in the audit and in the closed technical details on the comparison page.

The checklist judge runs after the deterministic checklist has already passed, and only when `FEATURE_LLM_REVIEW=block`. It returns `pass` or `block` plus a short paragraph for the reviewer. It does not set classification, routing, policy, facts, deadline, or citations. The customer message stays the fixed template, so a judge failure cannot change that sentence.

Approaches 2 and 3 call that same model only when the rules leave the case open. A labeled denial, a conflict, and a rules class of unsupported, duplicate, or service are not sent. Ambiguous with no conflict may be sent. Unauthorized from complaint wording may be sent only when authorization is not supplied. The complaint is redacted before the call. A proposed class is kept only when the labeled authorization allows it: unauthorized only when the label is not supplied or denied; duplicate and service only when the label is confirmed or not supplied. A confirmed label on an unauthorized proposal does not stand, and the case goes to manual review. A denied label never reaches the model. Any other class with that label is a hard failure. Evidence is accepted only when it is exact complaint text after whitespace is collapsed. A quote that is not in the complaint is rejected, and approach 2 then keeps the rules class.

Approach 3 asks Jev first. Jev's model name defaults to `jev-latest`. The threshold in `config/rules/classifier.yaml` is a placeholder, `0.70`. A tie, a probability under that threshold, or an ambiguous option does not assign a class. An ambiguous Jev answer goes to manual review and does not call Clef or the configured model. When Jev returns a class and it matches the rules, that class is kept and the configured model is not called. When Jev is missing or its call fails, approach 3 asks Clef-flash with the same choice payload plus `instructions` on the choice question. An ambiguous Clef answer goes to manual review and does not call the configured model. A Clef class that matches the rules is kept. A disagreement asks the configured model, and that class stands only when it matches the rules or the ranker. A rejected reply still goes to manual review. If there is no configured-model client, or that call cannot run, the rules class stays (`ranker_disagreed_no_model`). When no ranker returns a class, the configured model is asked, or the rules class stays when that client is missing (`rules_only`, or `model_failed` when a ranker call failed). Jev cost is unpriced (`status` `unpriced`, no USD figure). Clef-flash list price is 0.038 USD per million input tokens and no output charge. An empty `JEV_BASE_URL` or `JEV_API_KEY` skips Jev. An empty `CLEF_API_KEY` or `CLEF_ACCOUNT_ID` skips Clef. A failed Clef call stores a short failure label, not the response body.

| Item | Value |
|---|---|
| Model id | `LLM_MODEL` in `.env`, kept exactly as written. An empty value uses `claude-haiku-4-5`. |
| Fallback | `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_MODEL`, `LLM_FALLBACK_API_STYLE`. Empty key or host means no fallback. Empty model uses `claude-haiku-5-5`. |
| API style | Anthropic Messages. `LLM_API_STYLE=anthropic`. The host is `AZURE_BASE_URL` in `.env`. It is not written in this file. A model call fails when that variable is empty. |
| Credential | `LLM_API_KEY` in `.env`, sent as `x-api-key`. Empty means no configured-model call. |
| Ranker | `JEV_BASE_URL`, `JEV_API_KEY`, `JEV_MODEL`. Leave the url and the key empty until a host is chosen. |
| Clef fallback | `CLEF_API_KEY`, `CLEF_ACCOUNT_ID`, `CLEF_MODEL`. Empty key or account skips it. Empty model uses `clef-flash`. The account id and key are not written in this file. |
| Checklist judge | `dispute-copilot agent-review`, after the checklist passes, when `FEATURE_LLM_REVIEW=block` |
| Classifier | Approach 2, and approach 3 on an eligible case when Jev and Clef are absent or failed, or when a ranker disagrees with the rules |
| Judge fallback | One hop. Timeout, HTTP error, or an unusable reply blocks the review with the stored note "The model reply was not usable." No second model. `FEATURE_LLM_REVIEW=off` skips the call and leaves the checklist result |
| CI / tests | `LLM_PROVIDER=null` and approach 1. Run the suite with `FEATURE_LLM_REVIEW=off`. A missing key cannot fail the live check, and the jobs do not set `CLASSIFIER_APPROACH` |
| Configured-model cost | `config/rules/cost.yaml` prices `claude-haiku-5-5` from list at 0.10 USD per million input tokens and 0.50 USD per million output tokens for prompts up to 100,000 tokens. Prompts over 100K tokens are not modelled. `claude-haiku-4-5` stays at 1.00 in and 5.00 out. The Azure invoice may differ from list. No measured token counts are recorded here |
| Jev cost | Unpriced. A stored number is not treated as a price |
| Clef-flash cost | List price in `config/rules/cost.yaml`: 0.038 USD per million input tokens, 0.00 USD per million output tokens. Token counts come from the provider `usage` object when present |

Structured output is parsed in the app from one JSON object. There is no schema enforcement on the provider call and no repair retry. A judge reply that is not `pass` or `block` with two to four sentences is stored as a block. A classifier reply is one JSON object with `class`, `reason`, and `evidence`.
